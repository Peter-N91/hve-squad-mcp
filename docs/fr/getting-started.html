Démarrage

Le moyen le plus rapide de démarrer est le mode délégué : le serveur s'exécute localement via stdio et VS Code GitHub Copilot invoque les agents réellement déployés. Aucun recours à Azure, aucune authentification et aucun coût de modèle au-delà de celui de votre propre session Copilot.

Prérequis

  • Node.js 20 ou version ultérieure. Le développement utilise Node 24 ; l'intégration continue (CI) utilise Node 22.
  • VS Code avec GitHub Copilot et la prise en charge de MCP activée.
  • L'ensemble d'agents hve-squad installé dans votre espace de travail. Le mode délégué renvoie une charte permettant à Copilot d'invoquer le persona correspondant ; les personas doivent donc être présents localement — installez le package APM hve-squad et exécutez apm install.

Le package npm est actuellement private et non publié : npx -y @hve-squad/mcp ne peut donc pas encore le trouver. Compilez le code source et configurez VS Code pour utiliser le chemin local dist/.

Compiler le serveur

git clone https://github.com/Peter-N91/hve-squad-mcp.git
cd hve-squad-mcp
npm ci
npm run build     # tsc -> dist/
npm test          # unit suites

Pour l'exécuter manuellement — il communique en JSON-RPC sur stdout et envoie ses journaux sur stderr :

node dist/src/server.js

L'enregistrer dans VS Code

  1. Ouvrez (ou créez) le fichier .vscode/mcp.json de votre espace de travail. Le package n'écrit jamais ce fichier à votre place — le modèle fourni dans les sources du squad est un exemple à copier.
  2. Ajoutez l'entrée du serveur, en indiquant dans args le chemin absolu du serveur compilé : 
    {
  "servers": {
    "hve-squad": {
      "type": "stdio",
      "command": "node",
      "args": ["C:\\path\\to\\hve-squad-mcp\\dist\\src\\server.js"]
    }
  }
}
  3. Rechargez VS Code. Les outils squad_* apparaissent dans le sélecteur d'outils Copilot.
  4. Sollicitez le squad en langage naturel — « effectue des recherches sur X avec le squad », « demande au squad de revoir cette conception ». Copilot choisit l'outil, le serveur renvoie la charte à exécuter en mode délégué, puis Copilot invoque le persona réel de l'ensemble d'agents installé.

Ce que « délégué » signifie réellement

En mode délégué, le serveur n'effectue aucun appel au modèle. Il détermine le routage correspondant à l'intention, charge la charte du persona concerné depuis le disque et la renvoie à l'hôte appelant. Votre session Copilot exécute l'inférence. C'est pourquoi le mode délégué n'entraîne aucun coût côté serveur et offre les mêmes fonctionnalités que le package complet — l'hôte exécute le même ensemble d'agents que d'habitude, simplement selon la table de routage propre au squad.

Le mode intégré distant repose sur le compromis inverse : le serveur exécute lui-même l'invocation du persona auprès d'Azure OpenAI, ce qui le rend accessible depuis Copilot Studio, mais entraîne des coûts.

Vérifier une modification

Si vous modifiez le serveur, voici les vérifications exécutées par la CI :

npm run lint                      # tsc --noEmit
npm test                          # unit suites
npm run test:conformance          # security conformance suites
npm run generate:check            # generated descriptor is not stale
npm run generate:connector:check  # generated connector is not stale
npm run snapshot:cast:check       # bundled cast matches its pin

generated/ est versionné dans le dépôt et régénérable. Si vous avez modifié tools.catalog.yml, exécutez npm run generate et incluez le résultat dans votre commit — la CI échoue en cas d'écart entre les sources et les fichiers générés, pas du fait de la modification elle-même.
